# 本地姿势审核标准

审核单位是**一个姿势组、一套人物骨架**。正面、侧面、斜侧、俯仰视共用人物、关节、大小和位置，仅相机不同。原始线稿之间允许存在比例、透视和细节偏差；应记录冲突，不能为迎合每张图分别修改骨架。

## 如何决定通过

先检查整个动作，再检查手脚和接触，最后检查保存后的重渲染。发现明确错误即可退回修正；只有候选通过项才需要完成全部视角与细节复核。`已初筛`不等于`已目审`，两者都不等于`通过`。

| 项目 | 通过要求 |
| --- | --- |
| 动作与重心 | 人数、左右肢体、站/坐/跪/卧、支撑方式及动作含义正确；不能把坐地做成悬坐、比心做成双手随意相碰。 |
| 多视角与相机 | 只用一套人物数据；正侧面结构合理，其余视角无新矛盾；相机、裁切偏差与身体姿势偏差分别记录。线稿之间有冲突时说明采用的解释。 |
| 头与颈 | 低头/抬头、转头、侧倾与参考意图相符；头与胸腰不能靠整个人物倾斜凑出方向。 |
| 手掌与手指 | 掌心、拇指对掌、指节弯曲、手指张合、指尖指向与接触符合动作。比心、托腮、合掌、指向、握持必须看局部放大；共用默认手型不能代替识别或逐组校正。 |
| 脚与脚趾 | 足尖、脚背/脚底朝向、踝关节、踮脚/平放关系合理。当前没有独立脚趾控制，涉及明显趾部动作时记为受限，不能假定已还原。 |
| 接触 | 该触地或接触身体的部位确实接触；无明显悬空或穿体。模型约 3 毫米的渲染离地余量可接受，但整个人物最低点触地不代表所有支撑点正确。 |
| 蒙皮与外观 | 肩、腋、髋、裆、肘、膝没有明显撕裂、过度塌陷或不合理拉伸。观察不到的细节记为未确认。 |
| 保存与复现 | 保存、重新导入、URL 恢复后，姿势和单指细节不丢失；相机切换不改变人物。通过记录绑定所审阅的原图、场景和渲染文件摘要。 |

各项记录 `pass`、`needs_correction`、`unobserved` 或 `not_applicable`，不使用加权总分掩盖关键错误。上半身参考只审核可见范围；未观察到的下肢不能宣称已准确还原。对动作意义关键且看不清的手型，需要补充证据或手动校正后重审。

## 数值检查如何使用

当前拟合器以图像长边为分母：关键点 RMS 超过 2.5%，或最大单点误差超过 8%，会发出复核标记。900 × 1200 图对应 30 px 和 96 px。相机到边界、脊柱反向代偿、关节到边界也会提示复核。

**这些只是提示，不是最终验收标准。** 它们比较的是模型推断的 2D 点，并非人工真值；原图比例/透视有差异或检测点本身错误，都可能导致较高误差。目视确认时应区分参考图差异、识别错误和实际 3D 错误。低误差也不能证明手掌/手指/足底朝向正确。

## 本地记录和通过数据

- 审核记录：`output/offline-pose/local-review.json`。
- 通过数据：`output/offline-pose/local-approved.json`；每组仅保存一套 `scene.figures`，不同视角放在 `cameras` 中。
- 实时读取有效通过数据：`/api/local-approved`。文件变更导致摘要不匹配时，原审核标为过期，不再计入通过。
- 本地审核与公开图库的 `verified` 分开统计，不自动发布到 GitHub。
- 本轮使用 `gallery-20261029-contact-v2` 结果。审核说明保留中文原文；转换进度、初筛和目视复核在页面中分别显示。

## 手指已确认的限制

这批 231 组可渲染草稿只有两种手指姿态，其中 230 组共用一种。当前界面只有整手握合；导入时的手指约束也会把指节统一回同一个握合值。完整手型需要补充：单指各节屈伸、根部张合、拇指对掌、常用手型，以及保留这些角度的场景导入导出。线稿手部与用户照片手部应分别验证，不能直接沿用身体点位检测的准确率。
